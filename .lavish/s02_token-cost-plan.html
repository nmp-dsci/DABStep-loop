plan s02 · after s01 · 15 Sep 2026 · champion v2, 9 of 10 on dev, 262k input tokens per question

Nine of every ten tokens the agent pays for are 49 Gmail, Calendar and Drive tool schemas it never calls: one harness option removes them, measured at −87% on the same question with the same answer

The cost is not in the agent. Logging the actual request bodies shows every API call carries a 95,810-character block of connector tool definitions the CLI inherits from the user-level claude.ai config, beside our 3,504-character system prompt and 296-character execute_python schema. The second, smaller cost is the one NVIDIA describes: the whole conversation, tool outputs included, is re-sent on every turn. The plan fixes the first with a setting, tests the second as the NVIDIA "reference instead of output" pruning, and runs both against the baseline on the same 10 questions to prove accuracy holds.

  • Measured, not inferred: the request bodies were captured through a local logging proxy on dev task 5; the per-call cache usage comes from the SDK's own transcripts for all 10 tasks.
  • Same agent throughout: v2 files, Haiku 4.5, effort medium, 20 turns. Only the harness changes.
  • Accuracy is the gate: a lean harness is adopted only if it passes what the baseline passes on the same questions, run side by side.

1 · where the cost is

1 · The 262k is a 27k-token prefix re-read on each of ~10 calls, and the prefix is not ours

  • The KPI: "tokens per question" on the demo Overview is the SDK's input_tokens per task — fresh + cache-read + cache-write summed over every API call in the session. v2 dev-10: 2,623,426 over 10 tasks, mean 262k, range 60k (task 5, 2 calls) to 726k (task 2697, 19 calls).

Why B is harness, not helper.py

  • The optimiser owns two files; pruning is a property of the tool result, which lives in the executor.
  • It is content-blind: a head + reference for anything over the cap, whatever the family. No answer key can hide in it.
  • It is reversible per run: a harness profile flag, recorded in run.json, nothing in the agent fingerprint.

What is not on the list

  • A smaller max_turns: it caps the long tail by failing it; the 19-call task is the one we most want answered.
  • Lower effort: medium is the fixed setting of the experiment, by your instruction.
  • Shorter system.md: it is 766 tokens and the optimiser's file; not a harness change.
  • Batching across tasks: the SDK is one session per task; sharing a prefix already happens through the cache.

7 · risks & open questions

7 · Risks — the fix is safe; the pruning is the part that can change an answer

Failure modes and the mechanism for each

  • The lean arm changes trajectories. Then the connector schemas were steering Haiku; the trajectory diff in §4 shows it, and the arm is still adopted if passes hold — a model that reads less is not a regression.
  • Pruning hides the number the agent needed. The reference re-opens it; the re-open count is measured; a task that used to pass and now re-opens more than twice flags the cap for raising, not the arm for rejecting.
  • The title switch has a side effect. Verified through the proxy on one task before any arm runs; if neither switch suppresses the call, A2 is dropped and the plan loses 1.9k per session, nothing else.
  • The connector config differs per machine. It does — this is user-level state; the CI image has no connectors, which is why the KPI was never questioned. strict_mcp_config makes the prefix identical everywhere; the gate check keeps it so.
  • Champion fingerprint. Unchanged: the fingerprint hashes the agent files, not the harness; the run records the harness beside it, so the two are never confused.
  • Session limit mid-arm. The cycle-5 guard: grep -c "session limit" on each results.jsonl; a poisoned arm is discarded and re-run, never mixed.

Open questions

  • Prune cap: 1,500 characters with a 600-character head (≈ 4 of 2697's 19 results would be cut) or 3,000 (≈ 1)? Default 1,500.
  • Adopt the lean harness for the loop sessions before or after the experiment? They cannot change an answer on dev-10 (they never run it); default before, so cycle 7 is already cheap.
  • Re-baseline the champion? After adoption, one lean run of v2 becomes the run the Overview KPI reads; the old 262k stays as the "was".
  • Branch: harness-cost, one PR for H0–H1, one for H2–H4.
